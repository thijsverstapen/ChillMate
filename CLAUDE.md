# ChillMate

A private harm-reduction companion for adults who use substances: care tools, safety
features, personal logs and private insights, before, during and after a night out.
No account, no cloud, no network. Everything stays on device.

Live on the App Store as [id6774212606](https://apps.apple.com/app/id6774212606).
iOS/watchOS 26, Swift 6, SwiftUI + SwiftData, five languages.

## The rule that matters most

**Never invent medical or dosing content.** Interaction ratings, dose ranges, onset
curves and overdose signs go to real users who make real decisions with them. New
safety content needs a citable source, and ideally a clinician, before it ships.
Wording changes to existing content are fine; new claims are not.

## Layout

This repo is one of three sibling directories under `~/Documents/ChillMate/`:

| Directory | What it is |
| --- | --- |
| `ChillMate Xcode Project/` | This repo. iOS + watchOS. The lead platform. |
| `CLAUDE ChillMate Android/` | Separate Gradle repo, chases iOS for parity. |
| `ChillMate Marketing/` | Not a repo. Screenshots, mockups, promo video. |

Six targets: the app, `ChillMateLiveActivityExtension` (which also hosts the Control
Centre widgets), `ChillMateWatchApp`, `ChillMateWatchAppWidget`, and the two test
bundles. `docs/` is a GitHub Pages site generated by `tools/build_site.py` — edit the
generator, never the generated HTML.

## Build and test

```bash
# Build
xcodebuild build-for-testing -scheme ChillMate \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO

# Unit tests. Pin the language or you inherit the simulator's.
xcodebuild test-without-building -scheme ChillMate \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:ChillMateTests -testLanguage en CODE_SIGNING_ALLOWED=NO
```

The `ChillMate` scheme is **iOS only**. The watch targets build with `-target`, which
is why CI builds them in a separate step:

```bash
xcodebuild build -project ChillMate.xcodeproj -target ChillMateWatchApp \
  -destination 'generic/platform=watchOS Simulator' CODE_SIGNING_ALLOWED=NO
```

If `xcodebuild` reports "requires Xcode, but active developer directory ... is a
command line tools instance", fix it with
`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, or prefix a single
command with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.

## Conventions the CI gates enforce

Run `python3 scripts/check_localization.py` and `python3 scripts/check_defaults_keys.py`
before pushing. They take seconds and are the first CI job.

- **Every user-facing string is localized into all five languages.** Adding a
  `String(localized:)` means adding the key to `ChillMate/Localizable.xcstrings` with
  `de`, `es`, `fr` and `nl` translations. English is the key itself and is not stored.
  Address the user informally in every language (`je`, `du`, `tu`, `tú`).
- **Every `UserDefaults` key lives in `DefaultsKey`** (`ChillMate/DefaultsKeys.swift`).
  No string literals at call sites.
- **No build artifacts tracked.** `DerivedData/`, `build/` and `*.log` are ignored.

## Tests

222 unit tests. CI runs the whole suite once per language, so an assertion that only
holds in English fails four times over.

- **Never assert an English literal against localized output.** Name the line through
  `SafetyLine` (`ChillMateTests/SafetyLine.swift`) and compare
  `text == line.localized`. Add a case there for any new safety line.
- Claims about wording belong in `SafetyTranslationTests`, which reads the shipped
  `.lproj` bundles and checks all five languages in one run.
- A negative assertion (`contains(x) == false`) against localized text is the
  dangerous shape: spelled in English it passes trivially in the other four languages
  while proving nothing.
- UI tests are advisory in CI, not a gate. They drive a real simulator and fail on
  shared runners for reasons unrelated to the change.

## Data

SwiftData, ten `@Model` types, `NightEntry` and `UserProfile` at the centre. Every
`@Query` uses a bounded descriptor from `ChillMateQueries` — never a bare sort. A
relative date in a descriptor is a different value on every read, so those are handled
there too.

`InteractionFinding` and `SubstanceInteraction` carry stable, language-independent
`id`s. Do not key anything on localized text.

### Changing the schema

`TypedRecordsMigration` is the worked example: it runs once, is idempotent, dedupes
children, and guards against a sync race. Follow its shape.

1. **Additive changes are free.** A new optional property, or one with a default, needs
   no migration — SwiftData handles it in place. Prefer this. Most schema changes can be
   made additive with a little thought.
2. **Anything else is a versioned migration.** Add a new `VersionedSchema`, add it to the
   `SchemaMigrationPlan` stages in order, and write the migration as a one-shot that can
   run twice without doing damage. The app may be killed mid-migration.
3. **Never renumber or reuse an existing stage.** Installs in the wild are at every
   version you have ever shipped.
4. **Test against real old data**, not a fresh store. A migration that only runs on an
   empty container proves nothing.
5. **Remember the backups.** `EncryptedBackupService` writes a versioned payload, so a
   schema change means a restore path for the old shape too. A backup taken on the
   previous version has to keep restoring.
6. **The watch and the widgets read the same container.** A schema change is not done
   until they build against it.

## The backup key

One 32-byte random key, minted on first use, held in the Keychain under
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, used with AES-GCM. No passphrase,
no derivation from user input, no rotation. `EncryptedBackupKeychain` carries the
full lifecycle in its doc comment.

Two consequences that are easy to forget and expensive to rediscover:

- **`ThisDeviceOnly` keeps the key out of iCloud Keychain**, so an encrypted
  backup can only be opened by the device that made it. The iCloud Drive file
  survives deleting the app or wiping and restoring *this* phone; it does not
  carry history to a *new* phone. Making it portable means a passphrase, which
  means a key a person can forget. That is a product decision.
- **Deleting the app destroys the key**, and with it every backup ever written,
  including the ones sitting in iCloud Drive.

## Releasing

`MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` appear ten times each in
`project.pbxproj` — change all of them together. Build numbers only ever go up, and a
number already uploaded to App Store Connect is spent even if the upload was wrong.

Release notes live in `Marketing/ReleaseNotes-<version>.md`, written in all five
languages, user-facing and specific: what changed and why it matters, not a changelog.

## Commit messages

A sentence that says what changed and why, in the imperative, no prefix or tag. The
body explains the reasoning, the failure it prevents, and what was verified. Recent
history is the reference:

> Let the Snapshot statics inherit the actor instead of asserting they are safe
>
> Translate the nine strings CI caught, and put the extension catalog behind the gate

Branch off `main` for anything non-trivial and open a PR so CI runs first.
